A repack of the 0.1.8 Linux test build with one fix: the game would not start on distributions with a newer Mesa.

### What was wrong

The game stopped before its window opened with **"No supported adapters"** and "Failed to initialize SDL renderer". The package carried its own 32-bit `libstdc++` and `libgcc_s`, older than the system's, and the system's Vulkan driver was given those copies when it loaded inside the game. On a recent Mesa the driver then failed to load. Reported on CachyOS with Mesa 26.2; other rolling distributions are likely affected.

### What changed

- The game no longer carries `libstdc++` and `libgcc_s`. It uses the system's 32-bit C++ runtime.
- Nothing else: the same game, launcher and netplay version as 0.1.8, so you can play with anyone on 0.1.8.

### Download and launch

Download **GDMelee-0.1.8.1-linux-x86_64.tar.xz**, extract it, and run `./GD-Melee`. Your saves, settings and mods from 0.1.8 are kept: they live outside the game folder.

You need the 32-bit C++ runtime, which a system with 32-bit graphics drivers normally already has:

| distribution | package |
|---|---|
| Arch, CachyOS, Manjaro, EndeavourOS | `lib32-gcc-libs` |
| Debian, Ubuntu, Mint | `lib32stdc++6` |
| Fedora | `libstdc++.i686` |

The other requirements are those of 0.1.8: an x86-64 Linux host, glibc 2.35 or newer, a 32-bit glibc runtime and a matching 32-bit Vulkan driver.

### Not tested on a graphics card yet

This build was checked for integrity and for which libraries the game loads, on a machine without a GPU. If it still does not start, run it as `VK_LOADER_DEBUG=error,warn,driver ./GD-Melee`, press Play, and send the newest game log.
