## 3. Estimate only: mix-and-match moves between Melee characters via Geno

Question: can a Melee-native character be exported to Geno, and then have moves and animations
mixed between characters (e.g. Mario with Captain Falcon's knee)? GD wants **an estimate of how much
would need building** to make "character X's move A replaced by character Y's move B" possible.
**Do not build it.** Answer with a scope estimate.

**Answer given to GD (2026-09-26), not built:**
- Normals, aerials and throws are mostly data: a row (clip + ftcmd script). The engine already plays
  one fighter's animation on another's skeleton through the common parts table (thrown animations,
  Kirby's copies). A move-graft tool copies Y's row into X's slot, remaps hitbox bones by common part
  (as install_ultimate.py does for its host) and scales offsets by fighter size. ~1-2 days for the
  tool plus LAB checks; each grafted normal after that is minutes plus tuning.
- Specials are fighter-specific C code that assumes the fighter's own data; each is rebuilt as Geno
  states (Halberd's approach), using the articles and on_hit being built for Sora. ~0.5 day simple,
  1-2 days complex, per special.
- Exporting a Melee fighter to a Geno-ready description: the Melee Kirby IR builder generalises to
  any fighter; ~1 day.

Starting points for the estimate: the Melee Kirby IR builder (`ports/ir/tools/build_melee_fighter.py`)
generalises to any retail fighter; the parts plan and role mapping (`plan_parts.py`) are what a
cross-skeleton animation would need; Geno's state/overlay surface is in `melee/docs/geno.md`.
