**Loading.** Two stages:
1. A frontend loading state after the SSS (`gmVsMode_State_Loading`) waits for the pipeline
   seed's core (`initial_pipeline_cache.core`, 143 pipelines) — `AuroraStats.seedPipelinesBuilt`.
2. The in-match hold (`gmscene.c`) now **freezes the match** (no GObj procs, so no fighters and no
   clock) and settles on the new `AuroraStats.urgentPipelinesPending` — pipelines something is
   drawing with that are not built, ignoring the seed's background warm-up. Before, it ran the
   procs under the panel and waited on the whole queue, so it always hit its 10 s ceiling with the
   match playing (GD saw a match start below 2:00). The release log prints the clock; it reads
   `120.00` on both the direct and the CSS > SSS > loading paths. After the frontend loading
   screen the hold is short-thresholded but still runs (~170 frames on a cold boot: the first
   frame's pipelines outside the seed core).
   Inputs during either stage are not buffered: nothing reads them, and a fighter sees a button
   held through the release as one press — inside the intro, before GO.

## Performance

Baseline and method: `_research/perf-baseline-2026-09-21.md` (`MELEE_PROFILE=1`,
`MELEE_PROFILE_SAMPLE=<s>` + `tools/port/prof_report.py`). The FIFO thread's
`reuse_array_upload` memcmp'd whole multi-MB snapshots on every miss (12–14 ms/frame); it now
compares only what the draw needs, and only the new tail when the array already holds a validated
prefix — **the tail rule is load-bearing**: without it per-triangle draws re-compare every time and
p50 goes to 28 ms. Still open from the baseline:
- `texture::sweep_object_caches` ~2 ms/frame on the game thread (`HSD_TObjSetup` calls
  `GXInitTexObj` ~313×/frame, each a cache entry kept 600 frames → ~188k entries walked per frame).
- Akaneia's p99 tail (~26 ms) — not yet profiled after the fix.
- The seed warm-up's `d3dcompiler_47` thread holds a core for minutes.
- **Latent hazard (not fixed):** the arena starts at `gw_mem1 + 0x3100`, so the statics' guest
  window 0x803B7280..0x804DEA9C is allocatable; an interpreted access there is redirected to a
  native static. Never observed. Fix: reserve that window out of the arena, as hardware does.
- `gw_ppc_static_native`'s 0x80300000 gate does not matter for performance (interpreter ≈0.2%).
- `MELEE_PROFILE`'s old `game_cpu` line is meaningless (15.6 ms GetThreadTimes granularity).

## Addendum (evening): .slp playback, determinism, Slippi codes

**Playback and recording.** `MELEE_SLP=<file>` plays a Slippi replay through the port (its
StartMeleeData + seed at fn_8016E730, processed inputs at Slippi's RestoreGameFrame point, frame
counter from -123). `MELEE_SLP_RECORD=<file>` writes the port's own matches as Slippi 3.19 replays;
record -> replay round trip is exact on every field (2622+ frames). `MELEE_STATE_TRACE=<csv>` writes
per-frame post-frame state (+ `.vel.csv`, `.seed.csv`, `.rand.csv`). Tools: `tools/replay/first_div.py`
(first divergence per field vs the console), `det_diff.py` (two port runs), `survey.py`, `batch_play.py`
(corpus crash hunt; 78 tournament replays, no real crashes). Corpus: `Gang-Steals/` (3561 Slippi 1.7.1
replays, `_build/replay_corpus.csv`). `selftest.ps1` now ends a run at the results screen / replay end.

**Console accuracy.** RustyJuicyElephant (3.19 online): stocks/percent never diverge; first difference
is a one-ULP x at frame 4056. Corpus replays play to the end with stocks matching. What made the
difference: UCF 0.73 (1.x/2.x) and 0.84 (3.x) - dashback, shield drop (+extended), cardinals, SDI,
Tumble, Shield SDI; neutral spawns; MSL sinf/cosf/tanf/atanf; PSVECNormalize as the SDK computes it;
gwtool lowers llvm.fmuladd to Gekko's fused single-precision multiply-add (exact in double,
identical on every SSE2 CPU) - rebuild every game TU after rebuilding gwtool; the version-aware
post-frame trace point (1.x/2.x sample before hits, 3.x after); per-frame seed resync for replays
without Frame Start. Known: the port's particle system draws a different number of RNG values than
the console in some effects (BF spawn effects), hidden by the per-frame seed resync but a real
difference; the camera widens ~35 frames late for a launched fighter (ftCamera_UpdateCameraBox never
assigns target_ext.v) - no measurable effect since the divergence it caused vanished.

**Determinism.** `MELEE_DETERMINISTIC` (default on during playback): one logic frame per render. Two
runs are bit-identical on every trace. The two render->logic couplings were removed (the magnifier's
and the fighter's off-camera flags are computed by logic at the end of each logic frame), so unpinned
runs are identical too - the prerequisite for rollback. Fourside's background writes JObj state in its
render callback (visual only; matters when hashing savestates).
