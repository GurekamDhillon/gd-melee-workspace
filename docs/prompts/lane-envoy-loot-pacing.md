# Lane packet: Envoy loot pacing: tame early drives, many keystones (2026-10-04)

Lua only, in the Envoy mod (`melee/pc/scripts/examples/envoy/`). No engine edits, no build. Start only when no other
lane is editing the Envoy mod (the bundle `scripts/main.lua` is generated by `python tools/port/envoy_bundle.py`; two
lanes regenerating it collide). Read `MENUS.md`, `PLAYTEST.md`, the design spec
`docs/superpowers/specs/2026-10-04-envoy-loot-and-modifiers-design.md`, `docs/TERMINOLOGY.md`, and the modules
`mod_pool.lua`, `mod_progression.lua`, `drive_loot.lua`, `drives.lua`, `drive_bag.lua`, `mod_engine.lua`,
`mod_budget.lua`, `foe_roll.lua`, `drive_text.lua`, `run_host.lua`, `run_screen.lua`, `run_hud.lua`.

## The owner, after his first full Classic run on this system (verbatim)
"Game felt pretty good". Then: "not everything needs a suffix, prefix, modifer, this, and that, all at once. The things
we gain early on should be more tame. Also keystones being 1/4, or 2/4 as you get further is okay, but having 30
keystones, and your spawn one is random would be cool, and we can just gain as many as we want, as long as we get far
enough into the game".
Evidence from his run's log: a stage-9 reward was "Lingering Frosted Purple Drive of the Crosswind and Malice" (four
affixes); the keystone allowance is `math.min(3, 1 + floor(depth/5))` (`mod_progression.lua:26`); the keystone pool is a
handful.

## Build
1. **Affix count grows with depth.** Early drives are one plain effect and read as one short line: no prefix and suffix
   stacked, no "of the X and Y". Propose and implement a curve (state it as a table in PLAYTEST.md), for example:
   depth 0-2: exactly one affix, Common only, names like "Green Drive: Smash attacks +10%"; depth 3-5: one or two,
   Uncommon appears; depth 6-9: up to three, Rare appears; depth 10+ and NG+ loops: up to four and Uniques. Rarity
   already has budgets: make affix count a function of rarity AND depth, so a lucky early Rare is still simple. The
   starter drive is one affix. Opponents follow the same curve (they roll from the same rules), so early opponents are
   simple too. Naming follows the count: one affix = no generated prefix/suffix chain. Keep the family budgets and the
   power curve honest: fewer affixes early must not silently lower late-run power; show before/after totals at depths
   0, 5, 10 and one NG+ loop.
2. **About thirty keystones.** Read the existing keystones and the modifier engine's vocabulary (triggers, conditions,
   effects, statuses Burn/Shock/Chill/Curse/Haste/Guarded/Momentum, hit rules, armour types, echoes, fighter caps,
   `gd.fighter_interrupt` for cancel windows) and write keystones up to about 30, each a build-defining rule with a
   real drawback, each expressible with what the engine has TODAY (list separately any good idea that needs engine
   work, do not fake it). Spread them across the families so every drive family has keystones that make it the centre
   of a build; avoid near-duplicates; one plain sentence each in `drive_text.lua` (effect, then drawback). No always-on
   afterimages (hard rule): any echo/afterimage keystone has a start event and an end.
3. **A random starting keystone.** At run start the player is given one keystone rolled from the pool with the run seed
   (announced with the starter drive: name, what it does, its drawback), equipped without using a choice. Offer a
   reroll or pick-one-of-three only if it is trivial; default is one random.
4. **No fixed ceiling on keystones.** The allowance keeps rising with depth and through NG+ loops (propose the rate,
   e.g. +1 every 5 depth, uncapped), shown as "Keystones n/allowed" as now. How further keystones are GAINED must be
   clear in play: propose and build one way (a keystone offered at each allowance step, as a choice of two or three at
   the stage-clear screen, is the obvious one) rather than a hidden list in the bag. Opponents may also hold keystones
   by the same allowance. Check the interaction limits: mutually exclusive keystones, what happens to drawbacks that
   stack, script budget with many keystones active (measure frame cost with 8 and 12 active against the 120 fps
   target, about 8.3 ms a frame total).
5. Tests (Lua, run from the WORKSPACE ROOT: `for f in melee/pc/tests/envoy_*.lua; do lua "$f"; done`), the bundle
   (`python tools/port/envoy_bundle.py` then `--check`), MENUS.md and PLAYTEST.md updated. Verify in the game by state
   readback if you can run it (frozen build via `GW_BUILD_ROOT`, never the build another lane is rebuilding); say what
   was only Lua-tested and that the look is unverified.
Report: the affix curve, the keystone list with one line each, which ideas need engine work, the allowance rule, how
keystones are gained in play, frame cost, tests, files changed.
