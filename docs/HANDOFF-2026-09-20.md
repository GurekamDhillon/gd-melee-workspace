## Aurora GXEnd issue (task #26 — public repo, can be fixed)

**File:** `extern/aurora/lib/gx/fifo.cpp`  
**Current state:** DevText overlay code on branch `agent/native-overlay`; loading screen code merged to master

**Problem:** Game never calls `GXEnd()` (it's `static inline` no-op in real hardware), so 82 `GXBegin` sites submit vertices aurora never processes.

**Current code flow:**
- `GXBegin()` → vertices written to FIFO buffer
- Vertices accumulate with state writes and other commands
- Without `GXEnd()`, buffer grows beyond actual vertex data
- `publish()` uses FIFO buffer delta, includes non-vertex data
- Aurora's divisibility check fails: "62 bytes for 4 vertices" (48 bytes actual + 14 bytes debris)

**Recommended fix (from research notes):**
Replace FIFO buffer delta with derived span: `nVerts × bytes_per_vertex` where bytes-per-vertex is calculated from VCD/VAT attribute format.

**Implementation notes:**
- Must track vertex count written since last GXBegin
- Must read/cache VCD (Vertex Component Description) and VAT (Vertex Attribute Table) from GX state
- `finish_draw()` should calculate span precisely before calling `publish()`
- This makes late/absent `GXEnd` harmless — span is self-contained

**Attempted but failed:** Shim-side close (tried counting attributes); attribute count unknowable from `gw_GXSetVtxDesc` alone because indexed attributes also cost writes.
